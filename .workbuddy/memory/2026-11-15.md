## 移除 Mock 模块 + 落地 P0/P1 算子与画像修复

背景：用户诉求「统计市是福州、结束时间在2026年、小区不为空，按小区统计条数」被误判成趋势分析。
决策：不再修补关键词 Mock，而是整体移除，改为「在线 LLM」或「显式规则 JSON」两条确定性入口。

### 改动
- `llm_provider.py`：删除 MockProvider / _mock_rules / _mock_extract / _mock_vision（约 730 行）、
  TASK_RULES/TASK_EXTRACT 标记；`get_provider()` 无 Key 或 `LLM_PROVIDER=mock` 抛 LLMError(kind=config)；
  `describe_provider` 改用 `provider.mode`；`diagnose_config` 无凭据返回 mode=unconfigured。
- `rules.py` / `doc_extract.py`：删除全部降级分支，失败明确报错；STEP_SCHEMA 从 `op_names()` 派生，
  STEP_OPS 改为动态视图；新增规则顶层 `task_type`（白名单 TASK_TYPES）；提示词补齐新算子与约束。
- `webapp.py` + `pages/workbench.html`：/plan 与 /run 支持 `rule_json` 表单（离线显式规则），
  导航徽章改为「LLM 未配置」；CLI 离线入口为 `--rule-file`。
- `ops/registry.py`：OpSpec 新增 `role`(filter/transform/analysis/output) 与 `produces_time_dim`，
  删除 mock_keywords / mock_build；全部内置算子注入 role。
- `ops/compiler.py`：别名回退只作用于条件类 `column`，不再改写 `by`/`index`/`group_by`；options 同理。
- `task_profile.py`：detect_task_type 改为「显式 task_type > 注册表 role + step_logs 成功状态 +
  结果列形态 + 时间周期数≥2」；date_part 单独不再判 trend；build_profile 传入 step_logs。
- 新增算子 19 个（总数 33 → 52）：
  P0 `date_filter` `count_rows` `cross_column_filter`；
  P1 `convert_unit` `text_normalize` `category_map` `dedupe_fuzzy` `assert` `profile` `mask_pii`
     `date_parse` `resample` `rolling` `lag` `corr` `having` `group_rank` `anti_join` `semi_join`。
  新文件：`ops/builtin/{filter_ops,clean_ops,quality_ops,time_ops,analysis_ops}.py`。
- `requirements.txt` 清理 Mock 描述 + 加 `<4` 等上限；新增 `.gitignore`（排除 .env / output*）。

  结果 1378 个小区 / 合计 5285 行，与手工口径逐行一致；task_type=summary，任务报告无「趋势分析」。
- `get_provider()` 无 Key / `LLM_PROVIDER=mock` 均抛 config 错误；`llm-check` 返回 unconfigured。

## 筛选为 0 修复 + 规则库 + 文档抽取节能/批量/宽表导出

### 根因（重要）
用户 20:00 那次运行的 `output/run_20261115_200052_11d964/rule.json` 把「结束时间在2026年」
写成 `{"column":"结束时间","operator":"eq","value":"2026"}`；该列真实值是
`2026-03-08T10:00:00+08:00` 完整时间戳，字符串全等恒为 False → 19954 行筛成 0。
误导源是 `rules.py::_RULES_SYSTEM` 第 12 条的旧示例（date_part + eq 2026）。
另：该规则顶层 `task_type: distribution` 也是 LLM 误标。

## 成交率结果获取失败根因修复 + 等待状态 + 抽取同步/异步

### 根因（双因，主因在执行/算子层）
运行 `output/run_20261115_222842_e535b1/rule.json`：「区县=鼓楼区 / 成交价为空=未成交，
不为空=成交 / 统计成交率」。LLM 生成 `filter → assign(isna/notna) → count_rows(状态)`，
`task_type=summary`。执行结果只有 `成交,2588` 一行，既无比率也无「未成交」组。
- 执行层主因：`clean_data` 的 `fill_missing="median"`（规则默认）在 steps 之前把
  `成交价(元)` 的 1472 个 NaN 填成中位数；`_filter_columns` 只收集带 `preserve_refs`
  的算子（filter/pct/dropna/date_filter），**`assign` 没登记**，其条件列的原始空值未还原
  → 2588 行全部 `notna` → 只有「成交」一组，比率无从计算。
- LLM 规则层次因：用 `assign + count_rows` 表达「率」只给计数不给比率列；`task_type=summary`
  与「率」不符；规则/执行层之间缺少「判空列不得被填充污染」的契约。
- 真实口径：鼓楼区 2588 行，成交 1116 / 未成交 1472，成交率 43.12%，成交/未成交 0.7582。

### 改动
- 新算子 `ops/builtin/rate_ops.py::rate`（第 53 个算子，role=analysis / hint=proportion）：
  按条件或判空分两类，一行输出「成交数/未成交数/总数/成交率/成交未成交比」，支持 `by` 分组。
  `ops/builtin/__init__.py` 追加导入；提示词目录由注册表自动派生。
- `ops/compiler.py`：新增 `_normalize_binary_rate()`，把「assign(互补 isna/notna) +
  count_rows(打标列)」**确定性归一**为 `rate`（带可审计 warning），旧规则重跑即正确；
  若后续步骤仍引用打标列则不改写。
- `ops/conditions.py::condition_columns()`：递归收集任意步骤中条件型字典引用的列；
  `rule_executor._filter_columns()` 改为「通用扫描 + 算子 preserve_refs」并集，
  新增算子自动受保护。还原方式由「整列覆盖原始值」改为 `_missing_masks()` /
  `_restore_missing_masks()`：只把原始缺失位置重新置空，保留文本归一与类型转换成果。
- `rule_executor.apply_steps` 后的 `safety_warnings`：单步 skipped 现在会在结果页显示
  「第 N 步未执行…结果可能不完整」，不再静默。
- `task_profile.py`：rate 判 proportion（显式 summary 声明会被判为矛盾并回退），
  新增 `_rate_profile()` 专用 KPI / 环形图 / 结论。
- `rules.py`：提示词新增 23) 成交率必须用 rate、禁止 assign+count_rows、24) 出现
  isna/notna 时禁止 `fill_missing="drop"`。
- `ops/builtin/filter_ops.py::_to_datetime()`：修复 pandas 3.x `format="mixed"` 在
  「带时区 + 不带时区」混合列里把 naive 日期解析成 NaT 导致年份筛选漏行的问题。
- **等待状态**：`webapp.render()` 统一注入 `WAIT_HTML`（遮罩 + 三阶段文案 + 计时 +
  进度条 + 禁用提交按钮防重复；JS 禁用时表单仍可用），`static/style.css` 加 `.dc-wait` /
  `.job-*` 样式；工作台/抽取/结果页的 POST 表单加 `data-stages` / `data-wait`。
- **同步/异步抽取**：新增 `jobs.py`（JobManager：带锁注册表 + 守护线程 + progress 回调 +
  状态机 queued/running/done/failed + JSON 快照 + 内存结果）；`doc_extract.extract_documents_batch`
  加 `on_progress`；`webapp` 新增 `/extract` 的 `mode=sync|async`、路由
  `/job/<id>`（meta refresh 2s 自动轮询）、`/job/<id>/status`（JSON）、`/jobs`（任务列表），
  新页面 `pages/job.html` / `pages/jobs.html`；异步任务完成后自动渲染抽取结果页。
  CLI 与既有同步行为不变。
