# 2026-11-16

## 比率类需求系统性重构（解决「换一个描述又不行」）

### 背景与根因
用户反馈「筛选市=福州；成交价为空=未成交、不为空=成交；统计未成交率」又失败。
复盘最近 5 次运行：同一描述 LLM 生成 4 种不同规则——正确 rate、两个互相矛盾的 filter、
`filter(isna)+rate+pct`、`assign+count_rows`；后 3 种结果为 0 或口径错误。
结论：**不是单个算子 bug，而是「率」语义没有程序化表达，全靠提示词软约束 LLM**。

### 设计：三层确定性保障（新增文件 `ops/intent.py`）
1. **生成层** `rules.generate_rules` → `apply_intent_plan`：比率意图高置信度解析出判据列、
   两类标签、目标方向、分母口径、筛选/日期/分组后，直接生成确定性 `rate` 骨架，
   LLM 输出降级为可替换输入（只保留纯清洗步骤）。
2. **算子层** `ops/builtin/rate_ops.py::rate` 通用化：`numerator=hit|miss`、
   `denominator=total|hit|miss`、`condition` 任意布尔、`by` 分组，一个算子覆盖成交率/
   未成交率/空值率/转化率/两类之比，无需为每种问法新增算子。
3. **编译兜底** `ops/compiler.py::normalize_rate_pipeline`：固定顺序
   `_normalize_binary_rate` → `_strip_judgement_filters` → `_fold_rate_tail_pct`
   → `_apply_rate_intent`，处理手填/规则库旧规则/绕过生成器的 /execute；幂等且带可审计 warning。
   低置信度意图只修方向、不猜判据列（救援分支仅从规则自身找判据）。

### 关键修复点
- `ops/intent.py::_target_alias`：剥掉「按区县分组统计」前缀，否则整句被当成率名，
  方向与分组列名都错（矩阵测试抓出）。
- `_parse_judge(require_pair=True)` 用 `_BARE_JUDGE_RE` 兼容「为空算未成交，不为空算成交」
  承前省略；`_STOP_WORDS` 防止把「的数据/统计」吞进标签。
- 判据列的判空 filter 一律从分母条件中移除（含矛盾 filter 去重合并），
  「小区不为空」等真实筛选完整保留。
- `task_profile._rate_profile` 按 numerator/denominator 动态生成 KPI 与结论；
  显式 `task_type=summary` 与 rate 矛盾时自动回退 proportion。
- 真实数据口径：福州 19954 行，成交 7702 / 未成交 12252，未成交率 61.4012%；
  鼓楼区 2588 行，成交 1116 / 未成交 1472，成交率 43.1221%。

### 验证

  aggregate/sort）、完整「描述→LLM 规则→意图编译→执行」链路、合成数据全形态收敛、
  真实数据两个方向。

### 约定 / 边界
- 新增比率类问法时优先扩 `ops/intent.py` 的解析与 `rate` 参数，不要新增专用算子或在提示词里堆特例。

  成交率-福州 7/10、未成交率-福州 3/10、成交率-鼓楼 5/8、成交价为空率 5/16、
  按区县分组未成交率（鼓楼 3/2）。
- **非比率类（6 例）**：分组计数、日期+判空、排序取前 N、脱敏、单位换算、透视，
  模拟遵守提示词的 LLM 输出，验证生成链路（校验/规整）→ 执行契约一致。

### 关键结论
- 比率需求的结果由**描述**决定，不受 LLM 输出波动影响（已用错误规则实证）。
- 非比率需求的结果依赖 LLM 输出质量，离线测试只能验证「给定输出→校验→执行」链路，
  无法验证 LLM 真实生成质量；这仍是需在线 key 才能覆盖的边界。
- `统计成交价为空率` 的正确语义：`condition=isna` + `numerator=hit`（命中即空值），
  不是 `numerator=miss`；两类标签为「命中/未命中」。

## 明细/清洗需求：前端接口级复现与系统性修复

### 用户反馈与复现
描述「提取区县为鼓楼区的数据，其中成交价空值置为0，其他字段空值置为null」被生成成
`task_type=summary + count_rows`，结果 1 行 2 列。用户要求**必须通过前端接口模拟**
（不能只在后端拼规则），且指出「规则生成总是不符合要求」。

用 `webapp.handle_request('POST','/plan')` → 取规则 JSON → `POST /execute` → `GET /result/<id>`
严格模拟浏览器，注入「故意错误的 LLM 输出」后复现：生成结果原样保留 summary + count_rows。

### 根因
比率意图有确定性骨架，但**明细/清洗意图没有任何骨架**——LLM 写成汇总就执行汇总。
即便 LLM 写对了 `fill`，全局 `fill_missing="median"` 也会在运行 steps 前把原始空值填掉，
导致显式填充静默失效；`_handle_missing` 还会把文本空值填 "Unknown"，无法表达 null。

### 修复
- `ops/intent.py` 新增 `DetailIntent` / `parse_detail_intent` / `_apply_detail_plan`：
  出现「提取/导出/列出/查出/筛选/清洗」等明细动词且**无分析词**时，确定性生成
  `filter` + 显式 `fill` 骨架，`task_type="detail"`，剔除 LLM 的汇总/比率/关联步骤；
  「其他字段空值置为 null」→ `options.fill_missing="none"`。
- `rules.probe_value_hints`：采样每列最多 60 行真实取值，把「提取鼓楼区数据」这类
  省略列名的裸词绑定到**唯一命中列**；多列命中直接放弃，绝不语义猜测。
- `etl_pipeline.PipelineConfig._FILL_METHODS` 与 `rules.FILL_WHITELIST` 新增 `none`；
  `_handle_missing(none)` 原样返回，保留原始空值，让显式 fill 生效。
- 提示词新增第 26 条：明细需求禁止汇总算子、空值填充用 steps.fill、
  保留 null 用 fill_missing="none"。
- 口语前缀处理：`提取/其中/把/将` 等不再被误当列名或筛选词。

### 验证
- 真实数据前端链路：鼓楼区 **2588 行 × 61 列**，成交价 1472 个空值全置 0，
  其余 33470 个空值保留，画像 detail，两步全 ok。
- 新增 `tests/test_frontend_flow_matrix.py`（15 例）：**全部通过 webapp.handle_request
  模拟前端表单**，覆盖 4 种错误 LLM 形态、4 种描述变体、日期+清洗、别名映射、
  /run 一键执行、统计类防误伤、比率骨架优先级。
- `pytest -q` → **659 passed, 28 skipped**；`compileall` 通过；诊断脚本已清理。

### 约定
- 新增「非统计类」需求支持时，优先扩 `ops/intent.py` 的骨架解析器，不要只改提示词。
- 涉及原始空值语义时，`fill_missing="none"` + 显式 `steps.fill` 是唯一可靠表达。

## 第三轮：跨年季度与均价语义根因治理

### 用户反馈
「去重 → 提取面积条件 → 每一年按季度分析平均成交单价趋势，成交单价=成交价/面积」
结果只有 1/2/3/4 季度、跨年混淆、不是季度均价；要求从原语设计层面根治，
并覆盖正常/跨年/缺失/重复/边界面积/异常价格多类场景逐步验证。

### 根因与修复
- `_workflow_date_parts` 首个粒度命中即 return，`date_part` 每个分量独立成列：
  改为细粒度强制带 year，新增 `date_part.bucket` 生成 `结束时间_年季度`（2026Q01），
  `aggregate.by` / `sort.by` 引用组合桶。
- 均价语义：逐条 expr 再 mean 只是单价算术平均；改为 aggregate 对分子分母各自 sum，
  aggregate 之后 expr 算 Σ分子/Σ分母，逐条均值保留对照列；分子/分母成对 notna。
- 去重键：裸「去重」用 `_infer_dedupe_key` 绑定 `标的号`；时间列固定为描述中的日期列；
  空日期行 `dropna`；count 分支补 `sort`；填充原语解析移到所有分句（此前分析分句里被忽略）。
- `rule_eval` 新增 `cross_year_bucket / year_missing_in_trend / avg_ratio_missing /
  dedupe_key_lost / dedupe_after_filter / outlier_not_handled`；`prompt_kit` H14/H16/H17/H18
  与 3 条组合负面示例；`forced_avg_ratio` 提示槽给出完整两步 JSON 结构。
- `task_profile` / `rule_eval` 补认 bucket 列；`_trend_profile` 优先选组合桶与最终均价列，
  过滤空期，均价场景 KPI 用整体均值而非累计合计。
