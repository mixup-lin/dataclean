### 发现并修复的根因
- `ops/intent.py::_workflow_date_column` 只按「列名含时间」的数量兜底；字段重命名后 `shipped_at + 签收时间` 会把「按发货时间趋势」误绑到签收时间。改为显式别名 > 完整列名 > 通用兜底，并由 `_workflow_analysis` 传入 aliases。

## 2026 年月均成交单价组合描述验证

### 发现并修复的根因
- `ops/intent.py::_workflow_analysis` 只把「2026 年」用于时间分桶，没有生成 `date_filter`；确定性意图编译替换 LLM 规则后把年份筛选彻底丢掉，结果混入 2025 数据。新增 `_workflow_date_filter`，在分析阶段把具体年份/日期区间/近 N 天编译成独立 `date_filter`，并放在该阶段 `date_part` 之前；「按月/按季度」仍只作为粒度，不误当筛选。
- `ops/rule_eval.py::_year_requested` 把「按年/季度/月」粒度也当具体时间范围，又因 `family == "trend"` 和有 year 分量而放过缺失筛选；改为只识别具体年份、日期区间与近 N 天，且不再因趋势族或年份分桶豁免。
- `rules.py` 在意图编译后按最终规则重新语义自检，避免 meta 残留上游 LLM 原始规则的问题。
- `ops/prompt_kit.py` 对齐编译器别名（`成交价(元)之和` / `面积(㎡)之和`），日期步骤位置说明改为「组合分析阶段放在 date_part 之前」，并修正核对清单重复编号。

### 验证
- 新增 `tests/test_workflow_primitives.py` 4 个回归：编译链、评测器缺失筛选、提示词对齐、前端 `/plan → /execute → GET /result` 全链路。
- 结果仅含 `2026-01` 至 `2026-03`，`2026-01` 均价 = 2415/2020 ≈ 1.195545，且与逐条均值 28.07625 不同。
- 全量 `pytest -q` → **788 passed, 29 skipped**；`compileall` 通过。

## 确定性编译器治理：从无条件替换改为语义守门

### 架构结论
- 不舍弃确定性编译器。比率等场景实测存在模型输出口径抖动，完全移除会把已知回归放回；但编译器不可能覆盖全部业务原语，不能无条件替换 LLM。
- 新策略：LLM 规则语义自检通过 → 原样保留；LLM 有问题且编译候选无问题/问题更少/解决了阻塞性问题 → 采用编译候选；编译候选结构非法、无收益或会破坏正确 LLM → 拒绝。
- `meta["intent_plan"]` 记录 `decision`（`preserved_correct_llm` / `compiled` / `rejected_*`）、候选问题数与原因；`meta["semantic_issues"]` 始终描述最终规则。

### 配套修复
- `ops/rule_eval.py`：识别同一列连续 `isna` + `notna` 造成的空结果；比值型均值必须成对过滤分子/分母 `notna`，否则空分子会稀释 Σ分母。
- `ops/prompt_kit.py`：带 rate 目标的分组场景优先归 rate，不再被“按 X 分组”误判为 count_group。
- `rules.py`：编译决策守门；新问题码 `avg_ratio_null_pair_missing` 避免“看起来正确但均价被稀释”的 LLM 规则被保留。

### 验证
- 新增测试覆盖：正确 rate 规则保留、正确复合规则保留、错误编译候选被拒绝、错误 LLM 规则仍触发编译。
- 多行业 49/49 通过；全量 `pytest -q` → **791 passed, 29 skipped**；`compileall` 通过。
